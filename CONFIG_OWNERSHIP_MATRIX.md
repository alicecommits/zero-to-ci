# Config ownership matrix

Tracks, per configuration concern, whether it's a common denominator
across multiple stacks (belongs in `scripts/cross-cutting/` or a shared
template) or genuinely stack-specific (belongs in one `skills/<category>/<stack>/`
folder only). Referenced from `CLAUDE.md`'s DRY-architecture note — read
this before adding a new stack, to catch a concern that should be
extracted instead of duplicated.

**2026-09-07 update:** package.json provisioning was rebuilt as a
checklist-cluster engine; `merge_package_json.py` (this matrix's old
row 1) is retired. Full design history —including two earlier retired
iterations and a real proven silent-overwrite bug in the second one —
lives in `major-evolutions/1_CHECKLIST_INTERPRETER_HANDOFF.md`. This
matrix's rows below are updated to match, but that handoff doc is the
canonical rationale source, not this file.

Status legend:

- **LIVE** — implemented, currently wired into a real stack.
- **STACK-SPECIFIC (by design)** — correctly scoped to one stack; the
  concern itself varies per stack, extracting it would be wrong DRY.
- **NOT YET EXTRACTED** — genuinely common across stacks per its own
  definition, but only one stack exists so far, so it's still living
  inside that stack's files. Flag to revisit once a second stack lands.
- **NOT STARTED** — stack it would apply to doesn't exist in this repo yet,
  or (new) the cluster covering it hasn't been written yet even for the
  one stack that does exist.

## Deferred by explicit design decision (not a gap — don't build yet)

The "execution / gating design" — how a checklist plan becomes an actual
file write, and who authorizes that (policy file / dual-mode wrapper /
audit record, sketched in `major-evolutions/1_CHECKLIST_INTERPRETER_HANDOFF.md`) — is
conceptual only. Nothing in that section is implemented, and it should
stay that way until picked up as its own explicit task. Don't infer from
its absence that anything here is unfinished by accident.

`ensure_line_in_precommit` (the husky pre-commit line-append mechanism
sketched in `major-evolutions/5_PRECOMMIT-HANDOFF.md`) is **now LIVE,
2026-09-08** — this paragraph is left here only as a pointer, not as a
"still conceptual" notice. See the `.husky/pre-commit` line-provisioning
row in the Matrix above for the implementation, and that same handoff for the
cross-cluster write-ordering problem it solves (two clusters each
wanting to contribute a line to the same file, in an order that's the
REVERSE of their evaluation-priority order — a real, distinct design
problem from anything `ensure_block_in_gitignore` had to solve).
Deliberately NOT built by generalizing `ensure_block_in_gitignore` — the
two are siblings, not one mechanism (gitignore blocks are
order-independent and multi-line; pre-commit lines are order-dependent
single invocations).

## Files this matrix should stay in sync with

- `scripts/spin_up.py` — dispatcher; routes `--frontend <stack>` to `scripts/stacks/frontend/<stack>.py`.
- `scripts/stacks/frontend/react-vite-ts.py` — thin pointer: invokes the checklist engine with this stack's rules file. Only atomic stack script that exists so far.
- `scripts/cross-cutting/checklist_interpreter.py` — the cross-cutting engine; template for what "extracted" looks like for the NOT YET EXTRACTED rows above.
- `skills/frontend/react-vite-ts/checklist-rules-react-vite-ts.yaml` — every cluster row above lives here until a second stack forces real extraction.
- `skills/frontend/react-vite-ts/package-versions.yaml` — single source of truth for every version pin the rules file references via `<package.version>` placeholders (resolved by `resolve_placeholders()` in the interpreter). Scoped narrowly: only packages this repo's own clusters install, never package.json's scaffolder-provided baseline — see that file's own header.
- `scripts/preflight.py` — verifies the checklist engine itself is wired up (interpreter present, this stack's rules present, `pyyaml` importable); will need a matching check per stack as more get added.
- `major-evolutions/` — the 6 ordered handoff notes (`0_FROM-PKG-DIFF-TO-CHECKLIST-RULES-PARADIGM.md` through `5_PRECOMMIT-HANDOFF.md`) this matrix's rows are distilled from; `1_CHECKLIST_INTERPRETER_HANDOFF.md` is the canonical design rationale — read it before editing the engine or any `checklist-rules-react-vite-ts.yaml`.

## When to revisit this file

- Adding a second frontend stack (vue-vite-ts, svelte-vite-ts, etc.) — check every NOT YET EXTRACTED row above; if the new stack needs the same cluster, that's the forcing function to actually move it into a shared rules file or `scripts/cross-cutting/`.
- Adding a first backend stack — same check, plus fills in the NOT STARTED backend row.
- (done, kept as an example of the pattern) Building `lint-staged-hooks` and `ensure_line_in_precommit` together closed what used to be 3 separate NOT STARTED rows and 2 stale standalone pre-commit-wiring rows — folding a cross-cutting mechanism's output into the columns of the clusters that use it, rather than giving the mechanism its own per-line row, is the template for any future "one mechanism, many owning clusters" concern.
- Any time a concern's row would need a new "stack-specific" entry that's actually identical to an existing one — that's a live DRY violation, not just a future one.
